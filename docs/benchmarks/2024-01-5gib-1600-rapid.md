# 1600 Rapid baseline: January 2024, 5 GiB

This benchmark records a reproducible baseline for the `maia3-1600-rapid`
preset. The book was built from the first 5 GiB of the January 2024 Lichess
standard rated archive and evaluated against an independent 1 GiB prefix from
February 2024.

## Environment

- Intel Core i5-1038NG7 (8 logical CPUs)
- 16 GiB RAM
- macOS 26.6.2
- CPython 3.9 with `python-chess` and the Python zstandard fallback
- Commit `881a9fd`

## Build result

| Metric | Result |
| --- | ---: |
| Compressed source prefix | 5 GiB |
| Games scanned | 16,340,647 |
| Games matched | 231,013 |
| Elapsed time | 2,650.971 s (44m 11s) |
| Average scan rate | 6,164 games/s |
| Peak RSS | 2,037.625 MiB |
| Polyglot entries | 68,335 |
| Emitted positions | 8,522 |
| Book size | 1,093,360 bytes |
| Deepest emitted ply | 20 |

`verify_book.py` reported a valid, key-sorted Polyglot file with no duplicate
records or illegal sampled moves. It checked all 68,335 entries structurally
and 768 moves through random legal walks.

The header-first filter improved the observed scan rate from roughly 300
games/s with full parsing of every record to 6,164 games/s over the complete
run. Only matching games are parsed by `python-chess`; no direct SAN parser or
parallel parser was introduced.

## Decisions supported by this run

- Keep the header-first filter. It is a large measured improvement while
  retaining the reference `python-chess` parser for accepted games.
- Do not prioritize direct SAN replay, multiprocessing, or disk spilling yet.
  A 5 GiB baseline now completes on a 16 GiB Mac with about 2 GiB peak RSS.
- Keep `max_plies=40` as a harmless backstop; the 25-game density threshold,
  rather than the fixed cap, currently determines practical depth.
- Use held-out total variation and per-ply coverage as the primary comparison
  metrics for the next parameter experiments.

The next controlled experiment should build the same source once for each band
width (25, 50, and 100) and compare all three against the same February sample.
Density correction and per-player caps should remain disabled until they beat
the unmodified sampling distribution on held-out data.
